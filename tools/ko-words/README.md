# ko-words — 번역이 쓰는 낱말 중 게임에 없는 것을 고정한다

`tools/ko-terms`가 **적어 둔 낱말**을 지킨다면, 이쪽은 **실제로 쓴 낱말**을 본다. 둘이 필요한 이유는 2026-08-18 전수 검수에서 드러났다.

## 왜 생겼나

대장(`overlay/ko/terms.json`)은 "여기 없는 게임 용어는 쓰지 않는다"는 규칙의 근거였는데, **그 규칙을 검사하는 것이 아무것도 없었다.** 대장 검사는 대장 안에서만 앞뒤를 맞춘다 — 행 번호가 있나, 그 행 원문에 그 낱말이 들어 있나. 번역이 대장 밖의 낱말을 써도 초록이었다.

그래서 대장이 28줄일 때 번역은 그 두 배가 넘는 게임 낱말을 쓰고 있었고, 그중 여섯이 게임에 아예 없는 말이었다.

- `장판` — 플레이어 은어. 게임은 `범위`(710)
- `손패` — 게임은 `카드`(9160대 블록)
- `방위` — 게임은 `방향`. 대장의 `not_found`가 이미 그렇게 적어 뒀는데도 쓰였다
- `월드` — 게임은 `서버`
- `훈련장` — 게임은 `초보자의 집`(8614)
- `우편함` — 게임은 `편지함`(1807)

전부 뜻이 통해서 읽는 사람이 안 걸렸다. **그럴듯한 것이 이 사고의 특징이다.**

## 무엇을 하나

`overlay/ko/ko.json`의 한국어와 손 케이스 패치(`overlay/patches/0009`)의 더해진 줄에서 한국어 낱말을 전부 뽑고, KR Addon 덤프에도 대장에도 없는 것만 남겨 골든으로 고정한다.

    uv run --no-project python tools/ko-words/ko_words.py           # 대조
    uv run --no-project python tools/ko-words/ko_words.py --write   # 골든 갱신

조사는 **떼어 낸 나머지가 게임에 있을 때만** 뗀다. `소지품에`는 `소지품`으로 잡히고, `장판`은 뗄 것이 없어 그대로 남는다.

## 0건이 곧 잘못은 아니다

모드가 지어야 하는 말이 있다. `길안내`·`발자취`·`경유지`는 게임에 없는 개념이라 게임 시트에 있을 리가 없다. 그래서 이 검사는 **"0건 금지"가 아니라 "0건 목록이 조용히 늘지 않는다"**이다.

빨개지면 둘 중 하나고, 어느 쪽인지는 사람이 정한다.

- 게임 낱말을 잘못 지어냈다 → 고친다
- 모드가 지어야 하는 말이 새로 생겼다 → `--write`로 갱신하고 **커밋 본문에 왜인지 적는다**

조용히 갱신하면 이 장치는 그날로 죽는다. `tools/strings-golden`과 같은 규약이다.

## 한계

- **Addon 시트만 본다.** 지명(PlaceName)·아이템 이름·캐릭터 생성 라벨은 다른 시트라 여기 0건이어도 지어냈다는 뜻이 아니다. `목소리`·`특징`·`하층`이 그런 자리다
- **부분 문자열 일치다.** 게임이 그 낱말을 어디선가 쓴다는 것까지만 말하고, **그 자리에서 그 뜻으로 쓰는지는 말하지 않는다.** 대장의 `HP` 항목이 초코보 경주 블록(9125)을 짚고 있던 것이 그 한계의 실례다 — 행 번호를 넣을 때는 앞뒤 행을 같이 봐야 한다
