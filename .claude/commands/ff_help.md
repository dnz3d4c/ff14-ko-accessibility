# /ff_help

**목록을 여기 손으로 적지 않는다.** 적으면 커맨드가 늘 때마다 낡고, 낡은 목록은 없는 것보다 나쁘다. 부를 때마다 실제 파일에서 만든다.

## 만드는 법

1. `.claude/commands/*.md`를 전부 찾는다.
2. 각 파일의 frontmatter에서 `description`과 `argument-hint`를 읽는다.
3. 파일 이름이 곧 커맨드 이름이다 (`ff_sync.md` → `/ff_sync`).
4. 아래 형식으로 낸다. 표를 쓰지 않는다 — 스크린리더로 읽는 목록이라 줄로 낸다.

       /커맨드 <인자>
         설명

5. 목록 다음에 **언제 무엇을 쓰나**를 짧게 붙인다. 아래 내용이 그것이다.

## 언제 무엇을 쓰나

**순서가 있다.** 아래에서 오는 변화가 위에서 오는 변화보다 먼저다 — [docs/upstream/sync.md](../../docs/upstream/sync.md) §9. 게임이나 KR 달라무드가 움직인 채로 업스트림을 올리면 무엇 때문에 깨졌는지 구분이 안 된다.

- **아무것도 모를 때** — `/ff_env check` 다음 `/ff_sync check`. 둘 다 아무것도 안 옮긴다
- **게임이 패치됐다 / 달라무드를 갱신했다** — `/ff_env`
- **원본 모드에 새 판이 나왔다** — `/ff_sync up <태그>`
- **vendor에서 손대고 패치를 안 뽑았다** — `/ff_sync patches`

## 이 커맨드들이 안 하는 것

- **판정 기준을 갖지 않는다.** 규칙은 `docs/`와 `tools/`에 있고 커맨드는 순서와 멈출 자리만 갖는다. 여기에 기준을 베끼면 그게 두 번째 사본이 되고, `tools/docs-check`가 안 보는 자리라 조용히 낡는다
- **인게임 판정을 못 한다.** 귀로 하는 판정은 사용자 몫이다. 커맨드는 실행할 것 하나와 무엇을 들어야 하는지까지만 낸다
- **문제가 있는데 커밋하지 않는다.** 각 커맨드의 `## 멈추는 조건`이 그 목록이다. 사람이 정할 것이 섞여 들어오면 거기서 멈추고 보고한다

## 배치와의 관계

`run\*.bat`은 그대로 살아 있고 커맨드가 그것을 부른다. 배치는 **한 가지 일**을 하고, 커맨드는 **그 일들을 어떤 순서로 엮고 무엇을 보고 판정할지**를 갖는다. 배치를 직접 돌려도 된다 — 목록은 [run/README.md](../../run/README.md).
