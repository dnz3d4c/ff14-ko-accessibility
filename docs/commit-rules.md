# 커밋 규칙

- 작성: 2026-08-17
- 적용 범위: 이 저장소(`ff14-ko-accessibility`)의 모든 커밋 + 업스트림에 보낼 PR 커밋
- 근거 조사: 업스트림 `derbruedi/ff14-accessibility` HEAD `30512023` 기준 커밋 140건 전수

## 0. 이 규칙이 왜 있는가

이 저장소의 변경은 두 종류로 갈린다.

- **업스트림에 되돌릴 수 있는 일반화** — 로케일 추상화, 게임 UI 라벨 외부화 같은 것. 한국을 언급하지 않고도 성립하고, 프랑스어·일본어 클라이언트에도 이익이다.
- **한국 전용 오버레이** — `ko.json`, KR 설치 경로, KR 시트 행 ID 매핑. 업스트림에 올릴 이유가 없다.

둘이 **한 커밋에 섞이는 순간 PR로 떼어낼 수 없다.** 그때 남는 선택지는 이력을 다시 쓰는 것뿐인데, 그 시점은 보통 몇 달 뒤다. 커밋 규칙의 목적은 문체 통일이 아니라 이 사고를 커밋 시점에 막는 것이다.

기여 계획은 아직 확정이 아니다. 이 규칙은 **확정될 때까지 선택지를 열어두는 비용**이고, 그 비용은 커밋마다 한 줄이다.

## 1. 전역 규칙에서 그대로 가져오는 것

`~/.claude/CLAUDE.md`의 커밋 규칙이 기본값이다. 여기서 바꾸지 않는다.

- 한글 우선, 전문 용어 금지, 동작 중심
- Phase 완료 직후 / 논리 단위 완결 시 / 대규모 변경 전 커밋
- 커밋 전 검증 명령 통과 확인
- `git status` 확인 후 완료 선언
- `Co-Authored-By: Claude ...` 트레일러 유지 — 업스트림도 같은 관행이라 충돌 없다(140건 중 117건 보유, 외부 기여자도 사용)

## 2. 이 저장소가 더하는 것

### 2.1 제목에 영역 접두를 붙인다

```
[영역] 무엇이 어떻게 달라지는지
```

| 영역 | 뜻 | 대표 경로 |
|------|-----|-----------|
| 상류 | 업스트림에 그대로 올릴 수 있는 일반화 | `patches/` |
| 오버레이 | 한국 전용 자산 | `overlay/` |
| 검증 | 테스트, 검증기, 골든 파일 | `tests/`, `tools/` |
| 문서 | 조사·설계 문서 | `docs/`, `README.md` |
| 벤더 | upstream submodule 포인터 이동 | `vendor` |
| 도구 | 빌드 설정, 스크립트, 저장소 설비 | `tools/`, 루트 설정 |

### 2.2 한 커밋에 영역을 섞지 않는다

특히 `[상류]`와 `[오버레이]`는 절대 섞지 않는다. 훅이 경로로 검사한다 — `[상류]` 커밋이 `overlay/`를, `[오버레이]` 커밋이 `patches/`를 건드리면 거부한다.

### 2.3 `[상류]` 커밋은 트레일러 두 줄이 필수다

```
Upstream-Files: FF14Accessibility/Services/UIReaderService.cs
Upstream-Subject: Bestaetigen-Button-Label je Sprache aus Daten lesen
```

- `Upstream-Files` — **업스트림 기준 경로**. 우리 저장소 경로가 아니다. 나중에 PR을 조립할 때 이 줄만 모으면 건드릴 파일 목록이 나온다.
- `Upstream-Subject` — 업스트림에 보낼 때 쓸 독일어 제목. **커밋을 쓰는 시점에 미리 써 둔다.** 몇 달 뒤에 diff만 보고 독일어 제목을 복원하는 것보다 지금 쓰는 게 정확하다. 움라우트는 `ae/oe/ue/ss`로 치환한다(§3.2).

### 2.4 본문에 검증 결과를 적는다

업스트림 관행이다(빌드 결과를 커밋 본문에 명기). 우리도 따른다.

```
빌드: 0 경고 0 오류
테스트: 22 통과
인게임: 안 함
```

**"인게임: 안 함"을 숨기지 않는다.** 업스트림 외부 기여자도 매 PR에 미테스트 사실을 자진 명기하는 게 관행이고(`STATUS.md:1380-1381`), 이 프로젝트에서 침묵은 "정상"이 아니라 "고장과 구분 안 됨"이다.

### 2.5 Conventional Commits를 쓰지 않는다

`feat:` `fix:` `chore:` 접두 금지. 업스트림 이력 140건 중 **0건**이 쓴다. 우리가 쓰면 상류 커밋을 옮길 때 제목을 다시 써야 한다.

### 2.6 줄바꿈은 LF

`.gitattributes`의 `* text=auto eol=lf`가 강제한다. 업스트림 blob도 전부 LF다(`git ls-files --eol` 153파일 전수 `i/lf`). 업스트림에는 `.gitattributes`가 **없으므로** CRLF로 오염된 PR을 보내면 diff 전체가 바뀐 것처럼 보인다. PR 전에 `git ls-files --eol`로 확인한다.

## 3. 업스트림 PR 커밋 규칙 (fork 저장소에서만)

우리 저장소 커밋은 업스트림 이력에 들어가지 않는다. PR은 upstream fork에 별도로 쌓고, 거기서는 **업스트림 관행을 그대로 따른다.** 아래는 명문 규정이 아니라 140건 전수 실측이다 — 업스트림에는 `CONTRIBUTING`도 `.github/`도 없고 `CLAUDE.md`에도 커밋 규칙이 없다.

### 3.1 언어는 독일어

- 실측: 독일어 139 / 영어 1(최초 커밋뿐). 유일한 외부 기여자 `bladestorm360`의 6커밋도 **전부 독일어**다.
- 유지관리자는 독일어권 시각장애인이고 커밋 메시지를 TTS로 읽는다. 한국어 커밋은 읽히지 않는다.
- 영어가 수용될지는 **미확인**이다(`README.en.md`가 있으니 가능성은 있다 — 추정). 첫 PR 전에 업스트림에 물어보는 게 싸다.

### 3.2 움라우트를 ASCII로 치환한다

`ä→ae`, `ö→oe`, `ü→ue`, `ß→ss`. 실측: 커밋 메시지 140건 전체에서 움라우트 **0회**. 같은 저장소의 `README.md` 본문은 실제 움라우트를 쓰므로 **커밋 메시지 한정 관행**이다. 이유는 기록돼 있지 않다(미확인).

### 3.3 제목은 서술형 평서문, 접두 없음

명령형이 아니다. 예: `Tauschfenster sagt auch, wie viele Marken man hat`. 자체 접두는 `Release v5.NN:`, `STATUS:`처럼 릴리스·문서용으로만 쓴다. 제목 길이는 중앙값 61자, 최대 122자 — 50/72 관례를 엄격히 지키지 않는다.

### 3.4 본문을 상세히 쓴다

140건 중 119건(85%)이 본문 보유. 무엇을·왜·어떻게에 더해 충돌 해결 내역과 빌드 결과까지 적는다. 외부 기여 선례는 **건드린 파일 목록과 additive 여부**까지 명세했다.

### 3.5 커밋을 자기완결 단위로 쪼갠다

업스트림은 외부 PR을 main에 바로 받지 않는다. 로컬 `test/prs` 브랜치에 **PR별 개별 머지 커밋**으로 쌓고, 버전 낭독을 "N개 기여가 들어간 테스트판"으로 바꿔 귀로 식별하며 인게임 테스트한 뒤, 승인되면 main에 fast-forward한다. 개별 되돌리기가 전제이므로 커밋이 자기완결적일수록 병합이 쉽다.

### 3.6 기존 사용자 결정을 뒤집는 변경은 본문에 명시한다

업스트림은 이미 내려진 결정(예: HP 퍼센트 표기)을 뒤집는 PR을 묵살 병합하지 않고 사용자에게 되묻는다. 우리가 동작을 바꾼다면 "이건 기존 결정의 변경"이라고 먼저 적는 게 안전하다.

## 4. 설치와 운용

훅과 템플릿은 저장소에 들어 있지만 git 설정은 클론마다 따로 걸어야 한다. 클론 직후 한 번 실행한다.

git config core.hooksPath .githooks && git config commit.template .gitmessage && uv run --no-project --with pytest pytest tools/commit-lint/tests -q

검증기는 `tools/commit-lint/commit_lint.py`이고 규칙 코드는 C1~C7이다. 훅은 `uv`가 없으면 **막는다(fail closed)** — 조용히 검사를 건너뛰면 규칙이 죽은 걸 아무도 모른다.

규칙을 고칠 때는 `commit_lint.py`와 이 문서를 같이 고친다. 영역 목록(`AREAS`)과 §2.1 표가 어긋나면 안 된다.

## 5. 아직 정하지 않은 것

- **업스트림 PR의 언어** — 독일어가 안전하지만 영어 수용 여부는 미확인(§3.1). 첫 PR 전에 질의한다.
- **fork 저장소를 언제 만들 것인가** — 기여 계획이 확정되기 전에는 `patches/`에 파일로 쌓는다. `[상류]` 커밋의 `Upstream-Files`/`Upstream-Subject`가 그때 그대로 PR 재료가 된다.
- **AGPL-3.0 LICENSE 파일 추가 시점** — 코드가 들어오는 시점(현재는 문서·도구뿐).
