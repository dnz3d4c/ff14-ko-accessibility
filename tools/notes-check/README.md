# notes-check — 릴리스 노트 본문

릴리스 노트가 판마다 다른 모양으로 쓰이는 것을 막는다.

    uv run --no-project python tools/notes-check/notes_check.py --version 5.88.0.1

## 왜 있나

**노트 본문을 만드는 코드도 본도 없었다.** 사람이 `dist\release\release-notes.md`에 손으로 쓰고 `run\release.bat`이 `--notes-file`로 올린다. 그런데 `dist/`가 `.gitignore`에 있어 본문이 판마다 사라진다 — `git log --all -- '*release-notes*'`가 0건이다.

다음 판을 쓸 때 이전 판을 볼 수 없으니 매번 새로 지어냈고, 그래서 `v5.88.0.0`과 `v5.88.0.1`의 절 이름과 종결형이 이미 서로 달랐다. 2026-08-22에 사용자가 `v5.88.0.1` 노트를 직접 고쳤고, 그 고친 판이 이 검사기의 원본이다.

커밋 트레일러 한 줄(`Release-Note:`)은 [`commit-lint`](../commit-lint/commit_lint.py)의 C14가 갖는다. 그 줄들을 모아 **노트 전체를 조립하는 단계**에 소유자가 없었고, 이 검사기가 그 자리다.

## 규칙 접두가 `N`인 이유

[`docs-check`](../docs-check/docs_check.py)가 커밋 검사기에서 `C` 규칙 코드를 긁어 문서와 대조한다. 여기서 `C`를 쓰면 코드 공간이 섞여 그 대조가 엉뚱한 최대값을 잡는다.

## 무엇을 보나

절 구성과 마크업과 `모드 변경사항:` 줄의 꼴이다. 규칙 표는 [release.md](../../docs/dev/release.md) §3-2가 갖는다 — 여기 베끼지 않는다.

**밀도로 재지 않는다.** 발행본의 강조 밀도 8.5%가 사용자가 쓴 `README.ko.md`의 11.6%보다 낮았다. 그래서 항목 하나를 통째로 강조했는지를 본다.

| 문서 | 목록 항목 | 전면 강조 |
|------|-----------|-----------|
| `overlay/ko/README.ko.md` | 135 | 0 |
| `overlay/ko/KEYS.ko.md` | 67 | 0 |
| v5.88.0.1 발행본 | 9 | 3 |

사용자가 직접 쓴 565줄 문서에 전면 강조가 0개다. 오탐 여지가 실측으로 0이고 사고는 전부 잡힌다.

## 기계가 못 보는 것

**`모드 변경사항:` 줄의 진위는 판정 불가가 확정이다.** 세 갈래가 다 막힌다.

1. 판 번호로 못 잰다 — 설치 프로그램만 고친 판에서도 플러그인 판 번호가 오른다. `v5.88.0.1`이 그 실물이다
2. 산출물 바이트로 못 잰다 — 판 번호가 zip 안 `FF14Accessibility.json`에 들어가고, DLL만 떼도 빌드마다 MVID가 바뀐다
3. vendor 포인터로도 못 잰다 — csproj 둘이 `vendor/` 안이라 판 올림만 하는 커밋도 gitlink를 움직인다

그래서 줄의 꼴만 본다. 산문 절의 도입 문단, 변경 항목의 순서와 취사, 강조 한 번을 어디에 쓸까, 제한사항이 현황과 맞나, 문장이 사실인가도 마찬가지로 사람이 본다.

## 어디서 도나

`run\release.bat`이 `gh`를 처음 부르기 전에 돌린다. 자산을 올리는 갈래와 노트만 고치는 갈래가 그보다 아래에서 갈리므로 **한 자리로 둘 다 덮는다.**

`--check-bump`처럼 서브루틴으로 빼지 않았다. 그쪽은 노트만 고치는 갈래를 일부러 통과시키려고 갈래 안에 뒀고, 노트 검사는 정확히 그 갈래를 막아야 한다.

## 본

`template.md`가 골격이다. **고정 문장은 사용자가 고친 판에서 떴고 발행본에서 뜨지 않았다** — 발행본을 베끼면 사용자가 지운 것이 되살아난다. 제목 아래 소개 문장과 설치 절의 폴더 구조 설명 둘이 그렇다.

자리표시자는 `{{...}}`를 쓴다. `<버전>` 꼴은 세 문서가 이미 다른 뜻으로 쓴다. `{{버전}}`만 `render()`가 채우고 나머지 셋은 사람이 채우며, 안 채운 자리는 규칙이 막는다.

본은 [`ko-style`](../ko-style/README.md)의 `USER_DOCS`에 들어 있다. 사용자가 읽을 문서의 본이라 습니다체이고, 안 넣으면 본을 만든 커밋에서 바로 빨개진다.
