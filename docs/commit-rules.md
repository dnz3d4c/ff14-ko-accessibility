# 커밋 규칙

- 작성: 2026-08-17
- 적용 범위: 이 저장소(`ff14-ko-accessibility`)의 모든 커밋 + 업스트림에 보낼 PR 커밋
- 근거 조사: 업스트림 `derbruedi/ff14-accessibility` HEAD `30512023` 기준 커밋 140건 전수

## 0. 이 규칙이 왜 있는가

이 저장소의 변경은 두 종류로 갈린다.

- **업스트림에 되돌릴 수 있는 일반화** — 로케일 추상화, 게임 UI 라벨 외부화 같은 것. 한국을 언급하지 않고도 성립하고, 프랑스어·일본어 클라이언트에도 이익이다.
- **우리만 쓰는 것** — `ko.json`, KR 설치 경로, KR 시트 행 ID 매핑. 보낼 이유가 없다.

둘이 **한 커밋에 섞이는 순간 PR로 떼어낼 수 없다.** 그때 남는 선택지는 이력을 다시 쓰는 것뿐인데, 그 시점은 보통 몇 달 뒤다. 커밋 규칙의 목적은 문체 통일이 아니라 이 사고를 커밋 시점에 막는 것이다.

기여 계획은 아직 확정이 아니다. 이 규칙은 **확정될 때까지 선택지를 열어두는 비용**이고, 그 비용은 커밋마다 한 줄이다.

## 1. 전역 규칙에서 그대로 가져오는 것

`~/.claude/CLAUDE.md`의 커밋 규칙이 기본값이다. 여기서 바꾸지 않는다.

- 한글 우선, 전문 용어 금지, 동작 중심
- Phase 완료 직후 / 논리 단위 완결 시 / 대규모 변경 전 커밋
- 커밋 전 검증 명령 통과 확인
- `git status` 확인 후 완료 선언
- `Co-Authored-By: Claude ...` 트레일러 유지 — 업스트림도 같은 관행이라 충돌 없다(140건 중 117건 보유, 외부 기여자도 사용)

## 2. 이 저장소가 더하는 것

### 2.1 제목에 영역 접두를 붙인다

```
[영역] 무엇이 어떻게 달라지는지
```

| 영역 | 뜻 | 대표 경로 |
|------|-----|-----------|
| 업스트림 | 원래 만든 사람한테 그대로 보낼 수 있는 것 | `vendor/ff14-accessibility` (kr-port 커밋) |
| 한국전용 | 우리만 쓰는 것 | `overlay/` |
| 검증 | 테스트, 검증기, 골든 파일 | `tests/`, `tools/` |
| 문서 | 조사·설계 문서 | `docs/`, `README.md` |
| 벤더 | 업스트림 핀 이동 | `upstream.json`, `vendor/ff14-accessibility` |
| 도구 | 빌드 설정, 스크립트, 저장소 설비 | `tools/`, 루트 설정 |

### 2.2 한 커밋에 영역을 섞지 않는다

특히 `[업스트림]`와 `[한국전용]`는 절대 섞지 않는다. 훅이 경로로 검사한다 — `[업스트림]` 커밋이 `overlay/`를 건드리면 거부한다(C7). 반대쪽 경계는 패치 파일이 사라지면서 경로가 아니라 vendor 포인터가 됐다 — §2.8의 C11이 본다.

### 2.3 `[업스트림]` 커밋은 트레일러 두 줄이 필수다

```
Upstream-Files: FF14Accessibility/Services/UIReaderService.cs
Upstream-Subject: Read the confirm-button label per locale from data
```

- `Upstream-Files` — **업스트림 기준 경로**. 우리 저장소 경로가 아니다. 나중에 PR을 조립할 때 이 줄만 모으면 건드릴 파일 목록이 나온다.
- `Upstream-Subject` — 업스트림에 보낼 때 쓸 제목. **커밋을 쓰는 시점에 미리 써 둔다.** 몇 달 뒤에 diff만 보고 의도를 복원하는 것보다 지금 쓰는 게 정확하다.

**언어는 영어다** (2026-08-18 결정). 근거는 §3.1에 있다.

### 2.4 코드가 움직이면 현황판도 움직인다

`[업스트림]`·`[한국전용]`·`[검증]`·`[도구]` 커밋은 [docs/status.md](status.md)를 같이 건드리거나, **안 건드리는 이유를 트레일러로 밝혀야 한다.**

```
Status-Board: W-01 진행
```

```
Status-Board: 해당 없음 - 오타 수정
```

값이 비면 면제가 아니다(`Status-Board:` 만 붙여 통과시키는 우회를 막는다). `[문서]`와 `[벤더]`는 요구하지 않는다 — 근거 문서를 고치거나 업스트림 포인터를 옮기는 것 자체는 할 일의 이동이 아니다.

이 규칙이 왜 있는가는 §0과 같은 이유다. **현황판이 코드보다 늦으면 며칠 만에 거짓말이 되고, 그 뒤로는 아무도 안 본다.** 비용은 커밋마다 한 줄이다.

### 2.5 `[벤더]` 커밋은 어디서 어디까지 올렸는지를 밝힌다

```
Upstream-Range: v5.85..v5.87 (3051202..a8ac7c5)
```

이게 없으면 "이 판에서 뭐가 들어왔나"를 되짚을 수 없다. 검사기는 C9다.

**핀(`upstream.json`)을 옮기는 커밋은 [upstream-changes.md](upstream-changes.md)를 같이 건드려야 한다**(C10). 업스트림은 독일어로 개발되므로, 이력을 한국어로 안 남기면 우리 저장소에 무엇이 들어왔는지 **읽을 수 있는 사람이 없다.** 절차는 [upstream-sync.md](upstream-sync.md) §6.

패치를 다시 쓴 경우는 `[벤더]`로 묶지 않는다. 핀 이동만 `[벤더]`고, 다시 쓴 패치는 원래 갈래로 나눈다 — 섞으면 §0의 사고가 그대로 난다.

### 2.6 본문에 검증 결과를 적는다

업스트림 관행이다(빌드 결과를 커밋 본문에 명기). 우리도 따른다.

```
빌드: 0 경고 0 오류
테스트: 22 통과
인게임: 안 함
```

**"인게임: 안 함"을 숨기지 않는다.** 업스트림 외부 기여자도 매 PR에 미테스트 사실을 자진 명기하는 게 관행이고(`STATUS.md:1380-1381`), 이 프로젝트에서 침묵은 "정상"이 아니라 "고장과 구분 안 됨"이다.

### 2.7 Conventional Commits를 쓰지 않는다

`feat:` `fix:` `chore:` 접두 금지. 업스트림 이력 140건 중 **0건**이 쓴다. 우리가 쓰면 보낼 커밋을 옮길 때 제목을 다시 써야 한다.

### 2.8 vendor 포인터는 세 갈래만 옮긴다

`vendor/ff14-accessibility`는 gitlink다 — 우리 저장소는 `kr-port` 커밋 하나를 가리키는 포인터만 기록한다. 그 포인터를 옮길 수 있는 갈래는 `[벤더]`·`[업스트림]`·`[한국전용]`뿐이다. `[문서]`·`[검증]`·`[도구]` 커밋에 포인터가 섞이면 거부한다(C11) — 그런 갈래에서 포인터가 움직이는 것은 대개 `git add -A`가 굴러간 포인터를 주워 담은 실수고, 통과시키면 vendor가 왜 바뀌었는지 이력에 안 남는다.

### 2.9 줄바꿈은 LF

`.gitattributes`의 `* text=auto eol=lf`가 강제한다. 업스트림 blob도 전부 LF다(`git ls-files --eol` 153파일 전수 `i/lf`). 업스트림에는 `.gitattributes`가 **없으므로** CRLF로 오염된 PR을 보내면 diff 전체가 바뀐 것처럼 보인다. PR 전에 `git ls-files --eol`로 확인한다.

## 3. 업스트림 PR 커밋 규칙 (fork 저장소에서만)

우리 저장소 커밋은 업스트림 이력에 들어가지 않는다. PR은 upstream fork에 별도로 쌓고, 거기서는 **업스트림 관행을 그대로 따른다.** 아래는 명문 규정이 아니라 140건 전수 실측이다 — 업스트림에는 `CONTRIBUTING`도 `.github/`도 없고 `CLAUDE.md`에도 커밋 규칙이 없다.

### 3.1 언어 — 지금은 영어로 적고, PR 직전에 정한다

실측은 그대로다. 독일어 139 / 영어 1(최초 커밋뿐), 외부 기여자 `bladestorm360`의 6커밋도 전부 독일어(2026-08-18 재확인). 유지관리자는 독일어권 시각장애인이고 커밋 메시지를 TTS로 읽는다.

그래도 **`Upstream-Subject`는 영어로 적는다.** 순서가 이렇다.

1. 이 트레일러의 값은 **언어가 아니라 시점**이다. 변경이 머릿속에 있을 때 "업스트림에 뭐라고 설명할 것인가"를 적어 두는 것 — 몇 달 뒤 diff만 보고 복원하는 것보다 정확하다.
2. **한 줄을 영어에서 독일어로 옮기는 것은 기계적이다.** 몇 달 된 diff에서 의도를 복원하는 것은 아니다. 되돌리기 싼 쪽을 지금 고른다.
3. 어차피 **PR은 `patches/`에서 조립하므로 메시지는 그 시점에 다시 쓴다.** 지금 무엇으로 적어도 잠기지 않는다.

**PR 직전에 독일어로 옮길 가능성이 높다고 본다.** 유지관리자가 TTS로 읽는데 독일어 음성이 영어 문장을 읽으면 알아듣기 어렵다. 수용 여부는 여전히 **미확인**이고(`README.en.md`와 영어권 기여자가 있으니 가능성은 있다 — 추정), 첫 PR 전에 물어보는 게 제일 싸다.

### 3.2 움라우트를 ASCII로 치환한다

`ä→ae`, `ö→oe`, `ü→ue`, `ß→ss`. 실측: 커밋 메시지 140건 전체에서 움라우트 **0회**. 같은 저장소의 `README.md` 본문은 실제 움라우트를 쓰므로 **커밋 메시지 한정 관행**이다. 이유는 기록돼 있지 않다(미확인).

`Upstream-Subject`가 영어인 동안 C6은 잠들어 있다 — 움라우트가 없으니 걸릴 일이 없다. **지우지 않는다.** 독일어로 돌아가는 순간 다시 필요하고, 그때 규칙을 새로 쓰는 것보다 남겨 두는 게 싸다.

### 3.3 제목은 서술형 평서문, 접두 없음

명령형이 아니다. 예: `Tauschfenster sagt auch, wie viele Marken man hat`. 자체 접두는 `Release v5.NN:`, `STATUS:`처럼 릴리스·문서용으로만 쓴다. 제목 길이는 중앙값 61자, 최대 122자 — 50/72 관례를 엄격히 지키지 않는다.

### 3.4 본문을 상세히 쓴다

140건 중 119건(85%)이 본문 보유. 무엇을·왜·어떻게에 더해 충돌 해결 내역과 빌드 결과까지 적는다. 외부 기여 선례는 **건드린 파일 목록과 additive 여부**까지 명세했다.

### 3.5 커밋을 자기완결 단위로 쪼갠다

업스트림은 외부 PR을 main에 바로 받지 않는다. 로컬 `test/prs` 브랜치에 **PR별 개별 머지 커밋**으로 쌓고, 버전 낭독을 "N개 기여가 들어간 테스트판"으로 바꿔 귀로 식별하며 인게임 테스트한 뒤, 승인되면 main에 fast-forward한다. 개별 되돌리기가 전제이므로 커밋이 자기완결적일수록 병합이 쉽다.

### 3.6 기존 사용자 결정을 뒤집는 변경은 본문에 명시한다

업스트림은 이미 내려진 결정(예: HP 퍼센트 표기)을 뒤집는 PR을 묵살 병합하지 않고 사용자에게 되묻는다. 우리가 동작을 바꾼다면 "이건 기존 결정의 변경"이라고 먼저 적는 게 안전하다.

## 4. 설치와 운용

훅과 템플릿은 저장소에 들어 있지만 git 설정은 클론마다 따로 걸어야 한다. 클론 직후 한 번 실행한다.

git config core.hooksPath .githooks && git config commit.template .gitmessage && uv run --no-project --with pytest pytest tools/commit-lint/tests -q

검증기는 `tools/commit-lint/commit_lint.py`이고 규칙 코드는 C1~C11이다. 훅은 `uv`가 없으면 **막는다(fail closed)** — 조용히 검사를 건너뛰면 규칙이 죽은 걸 아무도 모른다.

규칙을 고칠 때는 `commit_lint.py`와 이 문서를 같이 고친다. 영역 목록(`AREAS`)과 §2.1 표가 어긋나면 안 된다.

### 4.1 C8의 한계와 `pre-commit`이 메우는 것

**C8은 현황판을 *건드렸나*만 본다.** 트레일러 하나로 면제되고, 절끼리 어긋난 것은 안 본다. 그리고 `[문서]`·`[벤더]`는 아예 대상이 아니다. 그 틈으로 문서가 낡았다 — 2026-08-18에 25곳이 실제와 갈라져 있었고, 그중 제일 큰 게 `README.md`였다(현황판 §8-1).

그래서 `pre-commit`이 `tools/docs-check`를 같이 돌린다. **문서가 인용한 숫자를 산출물에서 다시 계산해 대조하고**, 현황판 §1·§2·§9가 서로 어긋나면 커밋을 막는다. 숫자를 손으로 옮겨 적는 문장을 새로 쓰면 `docs_check.py`의 `CITATIONS`에 자리를 등록한다 — 등록 안 한 인용은 아무도 안 지킨다.

## 5. 아직 정하지 않은 것

- ~~업스트림 PR의 언어~~ — **영어로 정해졌다**(2026-08-18, 사용자 결정). 트레일러(`Upstream-Subject`, §3.1)도 PR 제목·본문도 영어다. 업스트림에 묻지 않는다.
- **무엇을 PR로 보낼 것인가** — 디렉토리 기준(`patches/` vs `overlay/`)보다 좁다. 기준 둘이 더 있고 못 넘기면 **패치를 만들지 않는다**: ① 글섭 클라 없이 소스만 읽어 판정될 것 ② 명백한 기존 로직의 오류일 것(리팩터·구조 개선 금지). 원천은 [patches/README.md](../patches/README.md).
- **fork 저장소를 언제 만들 것인가** — 기여 계획이 확정되기 전에는 `patches/`에 파일로 쌓는다(쌓아만 두는 게 아니라 로컬에도 적용된다 — [patches/README.md](../patches/README.md)). `[업스트림]` 커밋의 `Upstream-Files`/`Upstream-Subject`가 그때 그대로 PR 재료가 된다.
- **AGPL-3.0 LICENSE 파일 추가 시점** — 코드가 들어오는 시점(현재는 문서·도구뿐).
