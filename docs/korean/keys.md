# 단축키 — 개발 쪽 실측

- 작성: 2026-08-17. 근거는 `vendor/ff14-accessibility/FF14Accessibility/Configuration.cs`의 기본값 52개 전수
- **이 문서는 키 목록을 갖지 않는다.** 사용자에게 주는 전체 목록은 [사용 안내](../../overlay/ko/README.ko.md) 4장과 [루트 README](../../README.md) 2장이 갖고, 설정 파일에 적는 독일어 이름 표도 거기 있다
- 여기 남는 것은 **키를 두고 실측하거나 판정한 것**이다

전에는 이 문서가 키 표를 아홉 개 갖고 있었다. 같은 목록이 저장소 안에 세 벌이었던 것이고, 이 저장소는 표가 둘로 갈려 기본 바인딩 셋이 조용히 죽은 사고를 이미 겪었다(W-04, 아래 §지금 안 되는 것). 목록은 한 자리에 두고, 두 문서와 소스가 어긋나지 않는지는 `tools/docs-check`의 `check_keys()`가 대조한다 (W-39).

## 설정 파일 이름이 독일어인 것

**모드가 그 이름들을 독일어 그대로 발음한다.** `알림. Strg+F12 눌러 수락한다.`처럼 나간다. 사람이 읽는 대응표를 우리가 만든 것과 별개로, 모드는 아직 옮겨서 말하지 않는다 — 현황판 [§4-7](../status.md#4-7-모드-키-이름이-독일어로-발화된다--모든-언어-w-21) (W-21).

## KR에서 게임과 겹치는 키

`N`(방향 안내)이 KR에서 **제작 메뉴를 연다.** 업스트림은 `N`을 "유일하게 비어 있는 낱글자"로 보고 배정했는데 KR에서는 그 전제가 틀렸다. 어느 키로 옮길지는 사용자 판단이라 현황판 [§7 D-2](../status.md#7-판단이-필요한-것)에 있다.

나머지 겹침 넷(PageUp·PageDown·Ctrl+End·Numpad5)은 카메라 조작이라 **화면을 안 보는 플레이에 결과가 없다.** 근거는 현황판 [§4-1](../status.md#4-1-키-충돌--5건-중-kr-고유는-1건-w-03) (W-03).

## 지금 안 되는 것

- `Ctrl+F` (깊은 던전 층), `Shift+Home` (로그 되읽기 맨 처음), `Alt+Home` (이전 로그 탭) — 키 이름 파서가 `Pos1`(Home)과 `Strg+F`를 모른다. 기동 로그에 `Unbekannte Tastenangabe` 경고로 찍힌다. 현황판 [§4-2](../status.md#4-2-기본-바인딩-3개가-조용히-죽어-있다-w-04) (W-04)

## 게임 자체 메뉴를 다루는 입력

모드가 붙인 키가 아니라 게임이 원래 받는 입력인데, **어느 화면에서 무엇이 통하는지가 화면마다 다르다.** 실측한 것만 적는다.

- **화살표 키** — 목록·대화상자 이동. 캐릭터 생성 외모 격자는 게임이 화살표를 무시하므로 **모드가 직접 넘긴다**
- **숫자패드 8 / 2 / 4 / 6** — 게임 자체 메뉴 이동. **서버(데이터센터) 선택 화면은 이것을 써야 읽힌다**
- **Enter** — 확인

**미확인**: 서버 선택 화면의 그 실측이 Dalamud를 붙인 뒤의 상태인지 아닌지를 기록에 안 남겼다. 로그인 화면 단계라면 모드가 아직 없으므로 사용자 문서에 옮길 수 없다. 확인되면 [사용 안내](../../overlay/ko/README.ko.md) 3장에 넣는다.

## 캐릭터 생성 외모 단계

실측으로 확인한 순서다.

1. **화살표 키** — 항목 값 바꾸기. 방향 넷 다 ±1이고 양 끝에서 멈춘다. "13 중 49" 식으로 읽는다
2. **Ctrl+F10** — 지금까지 고른 외모 전체 듣기
3. **Ctrl+F8** — 무작위로 다시 굴리기
4. **Enter** — 확인

이 화면의 항목 21개(2026-08-17 KR 실측): 얼굴 유형, 얼굴 윤곽, 눈, 눈썹, 코 모양, 입 모양, 머리 모양, 머리 색, 피부색, 눈동자 색, 눈동자 크기, 입술 색, 얼굴 치장, 얼굴 치장 색, 문신, 문신 색, 점 및 흉터 등, 체격, 키, 가슴둘레, 목소리 유형.

## 호환 상태 확인

`/acc compat` — 지금 어떤 답이 게임에서 오고 어떤 답이 KR 호환 계층에서 오는지 말해 준다. 대화 입력란에 치는 명령이다.

기동할 때도 **게임과 답이 달라질 수 있는 경우에만** 한 줄이 로그에 남는다. 현재 KR에서는 기어세트 마크 한 줄이다(`Gearset marks go by item ID`) — 같은 장비 두 개 중 하나만 세트에 들어 있어도 둘 다 표시된다는 뜻이다. 근거는 [environment.md](../dev/environment.md) §5.

## vnavmesh가 필요한 키의 판정 이력

자동 이동·따라가기·경로 미리 듣기는 vnavmesh가 있어야 동작한다. **깔려 있고 인게임 동작까지 확인됐다** — 대상 지정부터 도착 안내까지 자동 이동 전 구간이 통과했다(2026-08-18, [현황판 §9](../status.md#9-끝난-것)).

게임 패치 뒤에 다시 판정할 일이 생기면 숫자패드 3을 눌렀을 때 들리는 말로 본다 — [kr-runtime.md](../dev/kr-runtime.md) §10.
