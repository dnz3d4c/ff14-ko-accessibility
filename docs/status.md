## 3. 배포 — 지금 어떤 모양인가

`run\pack.bat`이 `dist/`에 **파일 두 개**를 낸다.

| 파일 | 무엇 |
|------|------|
| `FF14AccessibilityInstaller-KR.exe` | 자체 포함 단일 EXE (162MB). 받는 쪽에 .NET 설치를 요구하지 않는다 |
| `FF14Accessibility.zip` | KR 패치가 들어간 플러그인 빌드 |

폴더째 옮기면 어디서든 돈다 — 설치기는 **자기 옆의 zip을 먼저 본다.**

설치기가 하는 일은 [kr-runtime-setup.md](kr-runtime-setup.md) §3~§8을 전부 대신하는 것이다. 프로필 부트스트랩 3종, `DALAMUD_RUNTIME`, 플러그인 배치, vnavmesh 내려받기, `dalamudConfig.json` 시딩. 근거와 KR화한 지점은 [overlay/patches/README.md](../overlay/patches/README.md) `0006`.

**아직 없는 것은 릴리스 채널이다.** 그래서 설치기가 인터넷에서 우리 플러그인을 받지 못하고 옆의 zip에 의존한다. 채널을 열지는 §7 D-1이다.

### 3-1. 공식 빌드로 바뀐 것 (W-29)

**설치기가 넣는 자리가 바뀌었다.** `devPlugins`(개발용)에서 `installedPlugins\FF14Accessibility\<버전>\`(정식)으로. Dalamud가 이제 보통 플러그인으로 보고, 모드의 플러그인 목록도 `개발용 플러그인`이라고 말하지 않는다. 조건 셋(버전 폴더 이름·`InstalledFromUrl`·프로필 GUID)과 근거는 [kr-runtime-setup.md](kr-runtime-setup.md) §7, 패치는 `overlay/patches/0012`.

같이 바뀐 것.

- **기본 언어가 한국어다.** `Auto`는 윈도 표시 언어를 따라가서, 영문 윈도를 쓰는 한국 사용자가 영어를 듣는다 (`0014`)
- **기동 안내에서 호환성 문구를 뺐다.** `호환성 안내: 장비세트 표시는 아이템 ID 기준.`은 내부 기제 이름이라 로그와 `/acc compat`으로 옮겼다. 인사말과 키 충돌 안내는 그대로다 (`0013`)
- **개발 배포와 정식 설치가 서로를 걷어낸다.** 같이 있으면 같은 모드가 두 번 뜬다. `run\log.bat`이 `적재 경로`를 말하고 둘 다면 실패로 센다
- **낸 것을 다시 잰다.** `tools/pack-check`가 압축 내용·개인 흔적·매니페스트 버전을 대조하고, 설치기를 버리는 프로필에 대고 실제로 돌려 결과를 검사한다 (`run\pack.bat` 3단계)

**바로 둘 잡혔다.** 하나는 `dist`의 압축이 `5.85`인데 소스는 `5.87`이었던 것 — 두 판 뒤진 것을 배포물이라고 들고 있었다.

**다른 하나가 더 나쁘다. 배포물에 글로벌 빌드가 들어가 있었다.**

`run\check.bat`은 같은 소스를 KR(7.51)과 글로벌(7.55)로 두 번 빌드하고 **둘 다 같은 bin에 쓴다.** 마지막이 글로벌이라, 검사 직후에 패킹하면 글로벌 바인딩 DLL이 그대로 나간다. 그건 **적재는 되고 첫 장비세트 호출에서 죽는다**(`RaptureGearsetModule.IsItemRegisteredToGearset`가 KR의 7.51에 없다 — `overlay/patches/0001`이 있는 이유가 그거다). 게임 안에서, 그것도 `Ctrl+F6`/`Ctrl+F7`을 눌러야 드러난다.

고친 방식은 두 겹이다. `run\pack.bat`이 **KR로 다시 빌드해서** 담고, 담은 것을 `tools/asmref-check`로 **다시 잰다.** 검사 순서를 지키는 규율로는 못 막는다 — 실제로 이번에 그 규율이 있었는데도 나갔다. `run\check.bat`의 빌드 순서도 KR이 마지막이 되게 뒤집었다.

## 4. 알려진 결함

### 4-1. 키 충돌 — 5건 중 KR 고유는 1건 (W-03)

**넷은 업스트림이 알고 낸 것이다.** `README.en.md:416`이 "의도한 것이고 개수를 로그인 때 알려 준다"고 적어 뒀다. 카메라 줌·프리셋·초점이라 **전맹 플레이에 결과가 없다.**

| 모드 키 | 게임 기능 | 판정 |
|---------|-----------|------|
| PageUp / PageDown | 카메라 줌 | 의도됨 (시각 전용) |
| Ctrl+End | 카메라 프리셋 저장 | 의도됨 (시각 전용) |
| Numpad5 | 카메라 초점 | 의도됨 — 모드가 게임에서 이 키를 뺏는다 |
| **N** | **제작 메뉴 (MENU_CRAFT)** | **KR 고유 결함** |

`N`이 다르다. 업스트림은 `N`을 방위 안내에 배정하면서 **"유일하게 비어 있는 낱글자"**라고 근거를 적었다(`Configuration.cs:18`, 글로벌 키바인드 덤프 2026-07-10). **KR에서는 그 전제가 틀렸다.**

| 키 | 글로벌 (업스트림 기록) | KR (2026-08-18 실측 덤프) |
|----|------------------------|---------------------------|
| N | 비어 있음 | `MENU_CRAFT` |
| H | `MENU_CRAFT` | `MENU_MONSTER` |
| L | `MENU_LINKSHELL` | `MENU_LINKSHELL` |

근거는 `%USERPROFILE%\Desktop\FFXIV_Keybinds.txt` 52~58행 — 모드가 로그인마다 직접 저장하는 KR 실기 덤프다. 업스트림이 시각 전용이라 넘긴 넷과 달리 **이건 실제 메뉴를 연다.** 어느 키로 옮길지는 §7 D-2.

### 4-2. 기본 바인딩 3개가 조용히 죽어 있다 (W-04)

`Strg+F`, `Umschalt+Pos1`, `Alt+Pos1`이 매 기동 `Unbekannte Tastenangabe` 경고를 낸다. 원인을 짚었다 — **키 이름 표가 저장소 안에 둘이고 서로 갈라졌다.**

| 표 | 위치 | `F`, `Pos1` |
|----|------|-------------|
| `KeyNames.NameToVk` | `KeyNames.cs:22` | **있다** — A~Z를 생성하고 `Pos1`도 명시 |
| `Plugin.KeyNameToVK` | `Plugin.cs:727` | **없다** |

`ParseKeySpec`이 쓰는 것은 **`Plugin.cs`의 옛 표**다(`Plugin.cs:838`). 그래서 `Configuration.cs`가 기본값으로 주는 세 바인딩이 파서에서 걸러진다 — 깊은 던전 층 안내, 채팅 버퍼 처음으로, 이전 채팅 탭. `GetPluginKeys`가 `Vk<0`을 건너뛰므로(`Plugin.cs:727-729`) **`/acc keys` 충돌 보고에도 안 잡힌다.**

라이브 로그로 확정했다 — `Unbekannte Tastenangabe` 경고가 정확히 셋이다. **KR 무관이고 순수 업스트림 결함이다.**

**"표 하나를 지우고 `KeyNames`로 합친다"는 그대로 하면 안 된다.** `KeyNames.NameToVk`에 `NumpadKomma`(0x6E, VK_DECIMAL)가 없어서, Plugin 표를 지우면 스킬 메뉴 뒤로가기(`SkillMenuBack`, `Plugin.cs:900`)가 **조용히 죽는다.** 합치면 `UpdateKeyEdges` 루프도 25개→70개로 넓어지고 게임이 안 쓰는 키마다 새 경고가 뜬다. 쪼개는 쪽이 맞다 — **이름 둘(`F`=0x46, `Pos1`=0x24)만 더하면 버그가 죽고**, 표 통합은 별건이다.

덤으로 찾은 것: **`KeyNames` 클래스는 어디서도 안 쓴다.** V5.33에 들어와 한 번도 배선된 적이 없는데, 자기 XML 주석에는 *"`Plugin.ParseKeySpec`이 이 표를 본다"*고 적혀 있다 — 거짓이다.

**업스트림에는 안 보낸다** (판단이지 판정이 아니다, §6).

### 4-4. 사냥수첩 창이 안 열린다 — 게임 쪽이다 (W-15, 막힘)

`H`를 눌러도 무반응이다. 모드 문제가 아니다.

- 키바인드 덤프(게임에서 live로 뽑은 것, 2026-08-18 09:22)에 `MENU_MONSTER (260): H`가 있다
- 모드는 `H`를 안 쓴다 — 충돌 목록에 `N` 하나뿐이다
- 같은 시각 `J`(일지)와 `K`(설정)는 열렸다. 낱글자 키는 게임에 잘 들어간다
- 로그 전체에 `MonsterNote`가 **0번**이다. 창이 조용한 게 아니라 안 열렸다

같이 떠 있던 `PlayGuide`·`OperationGuide`·`QuestRedoHud`가 초반 튜토리얼 구간을 가리킨다. **사냥수첩이 아직 안 풀린 것으로 본다**(추정 — 메인 메뉴에 항목이 있는지로 확정된다).

데이터는 이미 읽힌다. `Klasse 1, Rang 1: 12 offene Ziele`는 시트와 메모리에서 나오므로 **UI가 잠겨 있어도 나온다.** 그래서 사냥 목표 갈래는 되고 창만 안 열리는 상태가 성립한다.

**단계 줄 판정(W-15)은 사냥수첩이 풀린 캐릭터가 있어야 한다.** 지금 캐릭터로는 확인할 방법이 없다.

### 4-5. 게임이 떠 있으면 배포가 실패라고 말한다 (W-17)

`runuild.bat`이 `[실패] 압축을 못 풀었다`를 내는데 **실제로는 반영된다.**

게임이 `Tolk.dll`과 `nvdaControllerClient64.dll`을 잡고 있어서 그 둘만 못 덮는다. 둘은 거의 안 바뀌는 네이티브 파일이고, 정작 바뀐 `FF14Accessibility.dll`은 덮이고 Dalamud가 자동으로 다시 적재한다(2026-08-18 09:27 실측: 덮임 → `Unloading`/`Finished loading` 연속).

`run/README.md`는 "게임이 켜져 있어도 됨"이라고 적어 뒀다. 그 말이 맞고, **판정만 틀렸다.** 잠긴 네이티브 파일은 실패로 세지 않아야 한다 — 지금은 성공한 배포를 실패로 읽어서, 진짜 실패와 구분이 안 된다.

### 4-7. 모드 키 이름이 독일어로 발화된다 — 모든 언어 (W-21)

`NotificationAccept`가 설정값 `KeyNotification`을 그대로 읽는다(`UIReaderService.cs:2882`). 기본값은 `Strg+F12`고, `Configuration.cs`의 키 이름은 전부 독일어다(`Strg`·`BildAb`·`Umschalt`·`Entf`).

**영어 사용자도 "Strg+F12"를 듣는다.** KR 고유가 아니라 독일어를 뺀 전 로케일이 같이 깨지는 자리다. 카탈로그로는 못 고친다 — 키 이름을 언어별로 옮기는 코드가 있어야 한다.

**한국어 사용자도 마찬가지다** — `알림. Strg+F12 눌러 수락한다.`로 나간다.

음성으로 새는 자리는 이 한 줄뿐이다(`_config.Key*`가 `AccessibilityStrings`로 들어가는 곳을 전수로 봤다). 도움말의 `Strg`들은 전부 독일어 arm 안에만 있어서 다른 언어로는 안 샌다.

고칠 자리는 이미 있다 — `KeyNames.Speak()`가 발화용 이름표를 갖고 있는데 독일어 전용이고, 그나마 **아무도 안 부른다**(§4-2). 저장된 이름은 못 바꾸므로(바꾸면 기존 바인딩이 다 무효가 된다) 발화 시점에만 옮긴다. 지어낼 낱말은 없다 — `Strg→Ctrl`, `Umschalt→Shift`, `BildAuf→Page Up`, `Pos1→Home`, `Entf→Delete` 전부 윈도 표준 영어 이름이다. `W-04`와 같은 파일이라 묶어서 고친다.

**업스트림에는 안 보낸다** (판단이지 판정이 아니다, §6). 근거: [ko-review-2026-08-18.md](ko-review-2026-08-18.md) §6-3.

### 4-3. vnavmesh 설정 파일 없음 — 고치지 않는다 (W-08, 버림)

기동마다 `pluginConfigsnavmesh.json` FileNotFound로 `[ERR]`이 하나 뜨고 기본값으로 진행한다. 남의 플러그인이 자기 설정을 아직 저장하지 않았을 뿐이고, **업스트림도 이걸 손으로 만들어 주지 않는다.**

우리가 만들어 주면 vnavmesh 스키마에 우리가 묶인다. 그쪽이 필드를 바꾸면 우리가 깨진다. **남의 것은 남이 관리하게 둔다** — vnavmesh 전반의 방침과 같다(§3).

`run\log.bat`이 오류 개수를 세므로 이게 1건인 상태가 정상이라는 것만 알고 있으면 된다.

## 5. 한국어화 — 모드 본체는 끝났다

**모드 안내가 한국어로 나온다.** 게임이 주는 텍스트(NPC 이름·대사·창 제목)는 원래부터 한국어였고, 우리는 거기 손대지 않는다. 둘을 구분하는 것이 이 작업의 핵심이다.

**규모를 잘못 세고 있었다.** 삼항만 세서 "675문장"이라고 말해 왔는데, 텍스트가 삼항 말고 다른 데도 있었다. 지금 상태는 이렇다.

| 어디 | 몇 개 | 스냅샷이 지키나 |
|------|-------|------------------|
| `AccessibilityStrings` 삼항 | 688쌍 → **686자리 끝, 2자리 의도적 보류** (§5-2) | **예** — 옮긴 뒤에도 잡힌다 |
| 삼항인데 모양이 복잡해 못 읽은 것 | 41곳 중 **36곳 끝**, 나머지 5곳은 아래 튜플 사전이라 W-12 (`overlay/patches/0009`) | 아니오 — [유형별 정리](ko-hand-cases.md) |
| 설치기 `Installer/Loc.cs` | 147키 중 한국어 92개 — **나머지 55키는 옮길 것이 아니다** (§5-3) | 아니오 |
| `CharaMakeIconText` 튜플 사전 | 1,928건 | **아니오** |
| `CharaMakeShapeText` 튜플 사전 | 1,095건 | **아니오** |

**캐릭터 생성 묘사가 본체보다 4배 이상 많다.** 얼굴·머리모양·눈매를 사람이 손으로 묘사한 글이라 그렇다. `(De, En, BriefDe, BriefEn)` 튜플이라 삼항을 읽는 스냅샷 밖에 있다(W-12).

`CharaMakeShapeText.cs`는 **자동 생성물**이라 파일을 직접 고치면 안 된다 — `tools/icons/shapes.tsv`에 한국어 열을 붙여 다시 만든다. 그쪽이 오히려 쉽다.

**옮기는 자리는 C# 파일이 아니라 `overlay/ko/ko.json`이다** (W-18, §5-4). `(독일어, 영어)` 쌍을 키로 한국어를 적고 `tools/ko-apply`를 돌리면 소스가 다시 쓰인다. 소스를 손으로 고치면 검사가 막는다. 절차는 [ko-localization 스킬](../.claude/skills/ko-localization/SKILL.md) §0-1.

**결정 셋은 2026-08-18에 내려졌고, 말투는 인게임에서 확정됐다.** 말투는 둘뿐이다 — **한 줄이면 상태줄(명사형), 여러 줄이면 설명문(해라체).** 용어는 게임 한국어판을 따르고, 게임이 준 텍스트는 조사까지 그대로 둔다. 근거와 적용법은 [ko-localization 스킬](../.claude/skills/ko-localization/SKILL.md) §2가 갖는다.

가르는 기준을 처음엔 "자주 들리는가"로 잡았다가 틀렸다. 그러면 **"한 번 듣는 짧은 안내"가 어느 칸에도 없다** — 언어 전환 확인이 거기였고 해라체로 나가서 되돌아왔다. 기준은 길이고, 빈도는 짧게 써서 버는 것이 왜 큰지의 이유일 뿐이다.

**세는 말 하나는 옮기면 조용히 깨진다.** `CounterConnector`는 말하는 쪽과 읽는 쪽이 같이 쓰는데, 한국어 어순으로 뒤집으면 사냥수첩 목록이 통째로 사라진다 — 예외도 로그도 없다. 업스트림이 같은 자리에서 이미 한 번 당했다([상세](ko-hand-cases.md)).

**옮기기 전 원본을 찍어 뒀다** — `tools/strings-golden/golden/de-en.json`. 688쌍을 한 자 단위로 대조한다. 위 표의 "아니오"들은 아직 못 지킨다.

**전수 검수에서 50곳이 나왔다** (W-20, [기록](ko-review-2026-08-18.md)). 거의 전부 용어였고, 대장 자체도 한 줄 틀려 있었다(`HP`가 초코보 경주 행을 짚고 있었다). 대장은 112개가 됐고 `tools/ko-words`가 "쓴 낱말이 게임에 있나"를 검사한다.

**용어 하나를 지어냈다가 잡혔다.** 스킬에 `Aetheryte → 에테라이트`라고 "결정"으로 박아 놨는데 로그·덤프 전체에서 그 표기가 **0건**이었다. 지웠다. 확인된 것만 표로 남기고 모르는 셋(Aetheryte·Action·Logout)은 모른다고 적었다. 게임 데이터에서 직접 뽑는 도구가 W-13이다.

**순서는 §2 표가 갖는다.** [ko-client-port-feasibility.md](ko-client-port-feasibility.md) §13에도 단계 목록이 있지만 그건 **착수 전 계획이고 조사 시점 그대로 동결된 문서**다 — 실제 진행과 어긋난 지 오래고, 앞으로도 안 맞춘다.

### 5-1. 채팅 묶음 — 옮겼고 귀로 확인할 차례

74쌍이 82자리에 붙었다. 설정 메뉴, 버퍼 이름, 탭·채널 줄, 기록 안내, 그리고 **들어오는 줄마다 앞에 붙는 채널 접두**까지다.

**채널 이름은 게임 것을 그대로 썼다.** 지어내지 않고 Addon 645~655행에서 뽑았다 — 말하기·외치기·떠들기·파티·연합 파티·귓속말·자유부대, 그리고 혼잣말(Echo, 1912행).

짐작했으면 틀렸을 자리가 둘이다.

- **`채팅`이라는 낱말이 게임에 없다.** 19,592행에 0건이고, 게임은 `로그`(로그 필터·로그창)와 `대화`를 쓴다. 그래서 모드도 그렇게 말한다
- **Echo는 `혼잣말`이다.** 음차가 아니다

**어순을 바꾼 자리가 하나 있다.** `ChatFromLine`이 `{prefix} from {sender}: {message}`인데 한국어는 `{sender} {prefix}: {message}`라야 말이 된다 — `모모디 말하기: …`. 보간 자리 이름은 안 건드렸고 순서만 옮겼다. 자리 집합이 같은지는 도구가 검사한다.

**여기가 인게임 판정이 필요한 이유다.** 말투는 눈으로 못 고른다. 첫 여섯 문장 때도 해라체로 나갔다가 듣고 되돌렸다(§2-3 스킬).

### 5-2. 일부러 안 옮긴 두 자리

688자리 중 686을 옮겼다. 남은 둘은 못 한 게 아니라 **옮기면 안 되는 것**이다.

**`CounterConnector`(`von`/`of`)** — 모드가 자기가 찍은 문장을 다시 읽는다. `UIReaderService.TryParseSpokenProgress`가 `"3 von 48"`을 공백으로 셋으로 쪼개 가운데를 이 상수와 글자까지 비교해서 토벌수첩 줄을 알아본다. 한국어는 전체를 앞에 두므로(`48 중 3`) **낱말만 바꿔서는 안 되고 `Counter()`와 읽는 쪽이 같이 움직여야 한다.** 그건 번역이 아니라 코드 변경이라 별도 작업이다(`W-19`). 지금은 영어로 나간다.

**`{name}: {distance}, {direction}.`** — 독일어와 영어가 **글자까지 똑같다.** 양쪽이 같은 갈림길은 옮길 것이 없다. `AttributeValue`에 이어 **두 번째로 찾은 "있으나 마나 한 갈림길"**이고, 둘 다 업스트림에 보낼 거리다(§6).

### 5-4. 왜 한국어가 패치가 아니라 카탈로그인가 (W-18, 끝남)

6문장일 때는 `overlay/patches/0008`이 32줄이었다. **W-06이 끝나면 같은 패치가 700줄이 된다** — 688쌍을 `AccessibilityStrings.cs` 안에서 고치는 diff다.

그 파일을 업스트림이 계속 고친다. 실측(vendor `main`):

| 구간 | 추가 | 삭제(=기존 줄을 다시 씀) |
|------|------|------|
| v5.81 → v5.83 | 96 | 0 |
| v5.83 → v5.85 | 611 | **20** |
| v5.85 → v5.87 | 49 | 0 |
| v5.87 → v5.88 | 12 | 0 |

**8일에 릴리스가 7개다**(v5.81 08-10 → v5.87 08-17). 대개는 뒤에 붙이기만 해서 우리 hunk가 전부 깨지진 않는다. 하지만 v5.83→v5.85에서 기존 `IsGerman ? … : …` 삼항(HP/MP 줄)을 **실제로 다시 썼다.** 그리고 `git am`이 `-3` 없이 돌아서(`patch_check.py:141`, `upstream_sync.py:262`·`:558`) hunk 하나만 어긋나도 시리즈 전체가 abort하고 어디까지 멀쩡했는지 안 남는다.

**문제는 충돌 빈도가 아니라 해결 비용이다.** 손으로 쓴 diff는 손으로 푸는 수밖에 없고, 700줄을 스크린리더로 훑어야 한다.

**고친 방식**: 한국어를 diff가 아니라 **데이터로 저장한다.** `overlay/ko/ko.json`이 `(독일어, 영어) → 한국어` 표를 갖고, `tools/ko-apply`가 소스를 다시 쓴다. 패치 `0008`은 손으로 안 고치고 **생성물**이다. 업스트림을 올릴 때 충돌하면 푸는 게 아니라 버리고 다시 만든다 — 실패 모드가 "diff 충돌"에서 "카탈로그의 문장 N개를 소스에서 못 찾음"으로 바뀐다.

**옛 방식이 새 방식의 출력과 같다는 것을 증명하고 넘어갔다.** 부모 커밋에서 생성기를 돌린 결과가 손으로 쓴 `0008`과 바이트까지 같았다(줄바꿈 위치·정렬·`$` 접두 포함). 차이는 축약 주석 한 덩어리뿐이었고 그걸 생성기 쪽 문구로 맞췄다. 그 왕복 검사가 이제 pytest에 남아 있어서, **`0008`을 손으로 고치면 빨개진다.**

`git am`도 `-3`으로 바꿨다. 업스트림이 우리 hunk **옆에** 문장을 끼워 넣는 게 흔한데, 3-way 없이는 그 하나 때문에 시리즈 전체가 죽고 어디까지 멀쩡했는지도 안 남았다. 같은 줄을 양쪽이 다르게 고친 진짜 충돌은 그대로 실패한다 — 테스트로 양쪽을 다 실증했다.

W-12(캐릭터 생성 3,023건)도 같은 방식으로 간다.

### 5-5. 모드와 게임이 같은 기능을 다르게 부른다 (W-28)

`Ctrl+F7`은 게임이 가진 장비 최적화 기능을 부른다. **게임 화면의 버튼 이름은 `최강 장비`인데**(공식 가이드 `120`: "장비세트 옆의 '최강 장비' 버튼"), 모드는 `추천 장비 착용됨.`이라고 말한다. 듣는 이름과 화면에서 찾을 이름이 다르다.

**`tools/ko-words`가 못 잡는다.** `추천`도 `장비`도 게임에 실제로 있는 낱말이라 낱말 단위 대조를 통과한다 — **낱말은 맞고 이름이 틀린 것**이고, 지금 검사에는 그걸 볼 수단이 없다. 공식 가이드 코퍼스를 만들면서 처음 드러났다(W-27).

고칠 자리는 `overlay/ko/ko.json`의 두 문장(`추천 장비 착용됨.`, `추천 장비 착용 중.`)이다. 같은 부류가 더 있는지는 대장 낱말을 코퍼스와 한 번 훑어야 안다.

## 8. 이 문서를 쓰는 법

**기능 구현·수정·개선을 시작할 때 여기를 먼저 연다.** 없는 일을 하지 않고, 하는 일에 ID를 붙인다.

- 새 일이 생기면 `W-NN`을 새로 딴다. **ID는 재사용하지 않는다.**
- 상태는 `대기` → `진행` → `완료`. 접는 것은 `막힘`(밖의 조건 때문에 못 하는 것)과 `버림`(안 하기로 한 것)으로 구분한다.
- 완료한 항목은 §2 표에서 **지우고** §9에 한 줄로 옮긴다. 표가 길어지면 아무도 안 읽는다. 그래서 §2에 `완료`가 남아 있으면 안 된다.
- §2는 **우선순위 순**으로 적고, §1 "다음"은 거기 열린 것 중 **제일 높은 등급**을 가리킨다.
- §1 "지금"은 **덮어쓴다.** 이력을 쌓지 않는다 — 이력은 git log가 갖는다.
- 근거는 여기 쓰지 않는다. `docs/`의 해당 문서에 쓰고 여기서는 링크한다.
- **판단이 필요한 것은 전부 §7에 모은다.** 곁 문서에 "사용자 확인 사항"이라고만 적고 넘어가면 아무도 다시 안 본다 — 실제로 D-4가 그렇게 두 문서에 묻혀 있었다.

**커밋이 이 규칙을 강제한다.** `[업스트림]`·`[한국전용]`·`[검증]`·`[도구]` 커밋은 이 파일을 같이 건드리거나, 안 건드리는 이유를 트레일러로 밝혀야 한다. 검사기는 `tools/commit-lint`의 C8이다.

```
Status-Board: W-01 진행
```

```
Status-Board: 해당 없음 - 오타 수정
```

### 8-1. 그런데 커밋 훅만으로는 안 막혔다 (W-23)

**C8은 "판을 건드렸나"만 본다.** 절끼리 어긋나는 것도, 판 밖의 문서가 낡는 것도 안 잡는다. 그래서 2026-08-18에 실제로 이렇게 됐다.

- §1이 "남은 것은 캐릭터 생성 하나"라고 적어 두고, 바로 아래 §2에 P1이 셋 열려 있었다
- §5 표는 "설치기 55키 남음", 같은 절의 §5-3은 "할 것 없음"이었다
- `README.md`는 **12커밋 동안 아무도 안 열어서** "한국어화는 아직 시작 전"이라고 적혀 있었다. C8의 `BOARD_AREAS`에 `[문서]`가 없으니 검사 대상이 아니었다
- `675쌍`·`C1~C8`·`40곳` 같은 숫자가 네 문서에 손으로 복사돼 있었고, 원본이 바뀌어도 아무 일도 안 일어났다

**고친 방식은 ko-words와 같다 — 방향을 뒤집는다.** 문서가 인용한 사실을 산출물에서 다시 계산해 대조한다. `tools/docs-check`가 하고, `run\check.bat` 1단계 pytest에 들어 있다.

- **인용한 숫자**: 골든 쌍 수, 카탈로그 문장 수, 대장 낱말 수, 패치 개수, 커밋 규칙 코드의 최대값. 문서에 적힌 값이 다르면 빨개진다
- **인용 자리가 사라져도** 빨개진다. 문장을 고쳐 쓰다 정규식이 아무것도 못 찾으면 검사가 조용히 죽는데, 그게 제일 나쁜 실패다
- **판 자체의 정합**: §2에 `완료`가 남았나, §2와 §9에 같은 ID가 둘 다 있나, §1 "다음"보다 높은 우선순위가 §2에 열려 있나, ID가 겹치나
- **`README.md`가 상태를 다시 적지 않는다.** 베낀 것을 검사하는 것보다 안 베끼는 쪽이 싸다 — 상태 문단을 지우고 이 판으로 링크만 남겼다

## 9. 끝난 것

역순이다. 근거 문서가 있으면 링크만 남긴다.

- **2026-08-18** **업스트림 `v5.88`로 올림** — 시스템 설정 창을 고치는 릴리스다. 업스트림이 잡은 넷: 이름을 **노드 순서**로 찾다가 그래픽 탭에서 내내 **옆 줄 이름**을 말하던 것(이제 화면 좌표로 같은 줄 왼쪽 글자를 본다), 선택 항목이 어느 줄인지 안 말해 `흔들림 표현`(Addon 4155)의 열두 버튼이 다 똑같이 들리던 것, 서로 다른 버튼이 같은 낱말을 달면 0.5초 중복 차단이 안내를 통째로 삼키던 것, 선택 목록이 두 번 나가고 두 번째가 `스위치, 끔`이라고 **틀린 말을** 하던 것. 여기에 초당 프레임 표시가 다른 안내를 계속 잘라먹던 것을 **낱말이 아니라 변화 속도로** 걸러낸다 — `fps`라는 낱말에 걸어 두면 언어마다 다르고 소수점 하나에 샌다. **우리 쪽 손이 필요한 자리는 하나였다.** `0008`은 붙이지 않고 카탈로그에서 다시 만들었고(§5-4가 대비한 그대로다. 카탈로그 669개가 전부 제자리를 찾았고 업스트림이 고친 우리 문장은 없다), 새로 생긴 안내 문장 `ConfigPageWithCount`는 **골든 쌍이 688로 그대로인데도 늘어난 것**이라 조용히 지나갈 뻔했다 — 단수/복수 갈림길을 품은 보간이라 스냅샷 파서 밖이고, `unparsed`가 41에서 42로 오른 것만이 신호였다. 손 케이스 35곳이 36곳이 됐다(`설정 {count}개`, 설정은 Addon 4000) (W-30, [upstream-changes.md](upstream-changes.md), [ko-hand-cases.md](ko-hand-cases.md))
