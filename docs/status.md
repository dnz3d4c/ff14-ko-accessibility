## 3. 배포 — 지금 어떤 모양인가

`run\pack.bat`이 `dist/`에 **파일 두 개**를 낸다.

| 파일 | 무엇 |
|------|------|
| `FF14AccessibilityInstaller-KR.exe` | 자체 포함 단일 EXE (162MB). 받는 쪽에 .NET 설치를 요구하지 않는다 |
| `FF14Accessibility.zip` | KR 패치가 들어간 플러그인 빌드 |

폴더째 옮기면 어디서든 돈다 — 설치기는 **자기 옆의 zip을 먼저 본다.**

설치기가 하는 일은 [kr-runtime-setup.md](kr-runtime-setup.md) §3~§8을 전부 대신하는 것이다. 프로필 부트스트랩 3종, `DALAMUD_RUNTIME`, 플러그인 배치, vnavmesh 내려받기, `dalamudConfig.json` 시딩. 근거와 KR화한 지점은 [overlay/patches/README.md](../overlay/patches/README.md) `0006`.

**아직 없는 것은 릴리스 채널이다.** 그래서 설치기가 인터넷에서 우리 플러그인을 받지 못하고 옆의 zip에 의존한다. 채널을 열지는 §7 D-1이다.

### 업스트림에 있는데 우리한테 없는 것

전수로 봤다. **기능 구멍은 없다.**

| 업스트림 자산 | 우리 상태 |
|---------------|-----------|
| 외부 플러그인 의존 | **vnavmesh 하나뿐**이고 깔려서 동작한다. 소스 전체의 IPC 호출 15종이 전부 `vnavmesh.*`다 |
| 동봉 네이티브 DLL | `Tolk.dll`, `nvdaControllerClient64.dll` — 빌드가 같이 배포한다 |
| 설치기 EXE | KR판을 냈다 (§3) |
| Dalamud 플러그인 목록 읽기 | 모드 기능이라 그대로 있다 (Shift+F1/F2/F12) |
| UI 노드 덤프 (Ctrl+F5) | 그대로. KR 실기에서 22창 383노드 확인 |
| 키바인드 덤프 | 그대로. §4-1의 근거가 이걸로 나왔다 |
| `repo.json` (Dalamud 커스텀 저장소) | **없다.** 인터넷 자동 갱신 경로인데 릴리스 채널이 있어야 의미가 있다 (§7 D-1) |

`repo.json` 하나가 진짜 빈칸이고, 그것도 기능이 아니라 **배포 채널**이다. 플러그인 창이 ImGui라 스크린리더에 안 읽히므로 업스트림도 그쪽을 주 경로로 안 쓴다 — 설치기를 만든 이유가 그거다.

**GUI는 눈으로 확인할 수 없으므로 콘솔 경로를 남겨 뒀다.** "아무 일도 안 일어난다"의 원인은 늘 경로 중 하나다.

dist\FF14AccessibilityInstaller-KR.exe --check

## 4. 알려진 결함

### 4-1. 키 충돌 — 5건 중 KR 고유는 1건 (W-03)

**넷은 업스트림이 알고 낸 것이다.** `README.en.md:416`이 "의도한 것이고 개수를 로그인 때 알려 준다"고 적어 뒀다. 카메라 줌·프리셋·초점이라 **전맹 플레이에 결과가 없다.**

| 모드 키 | 게임 기능 | 판정 |
|---------|-----------|------|
| PageUp / PageDown | 카메라 줌 | 의도됨 (시각 전용) |
| Ctrl+End | 카메라 프리셋 저장 | 의도됨 (시각 전용) |
| Numpad5 | 카메라 초점 | 의도됨 — 모드가 게임에서 이 키를 뺏는다 |
| **N** | **제작 메뉴 (MENU_CRAFT)** | **KR 고유 결함** |

`N`이 다르다. 업스트림은 `N`을 방위 안내에 배정하면서 **"유일하게 비어 있는 낱글자"**라고 근거를 적었다(`Configuration.cs:18`, 글로벌 키바인드 덤프 2026-07-10). **KR에서는 그 전제가 틀렸다.**

| 키 | 글로벌 (업스트림 기록) | KR (2026-08-18 실측 덤프) |
|----|------------------------|---------------------------|
| N | 비어 있음 | `MENU_CRAFT` |
| H | `MENU_CRAFT` | `MENU_MONSTER` |
| L | `MENU_LINKSHELL` | `MENU_LINKSHELL` |

근거는 `%USERPROFILE%\Desktop\FFXIV_Keybinds.txt` 52~58행 — 모드가 로그인마다 직접 저장하는 KR 실기 덤프다. 업스트림이 시각 전용이라 넘긴 넷과 달리 **이건 실제 메뉴를 연다.** 어느 키로 옮길지는 §7 D-2.

### 4-2. 기본 바인딩 3개가 조용히 죽어 있다 (W-04)

`Strg+F`, `Umschalt+Pos1`, `Alt+Pos1`이 매 기동 `Unbekannte Tastenangabe` 경고를 낸다. 원인을 짚었다 — **키 이름 표가 저장소 안에 둘이고 서로 갈라졌다.**

| 표 | 위치 | `F`, `Pos1` |
|----|------|-------------|
| `KeyNames.NameToVk` | `KeyNames.cs:22` | **있다** — A~Z를 생성하고 `Pos1`도 명시 |
| `Plugin.KeyNameToVK` | `Plugin.cs:727` | **없다** |

`ParseKeySpec`이 쓰는 것은 **`Plugin.cs`의 옛 표**다(`Plugin.cs:838`). 그래서 `Configuration.cs`가 기본값으로 주는 세 바인딩이 파서에서 걸러진다 — 깊은 던전 층 안내, 채팅 버퍼 처음으로, 이전 채팅 탭.

**KR 무관이고 순수 업스트림 결함이다.** `[업스트림]` 후보 중 근거가 가장 단단하다 — 표 하나를 지우고 `KeyNames`로 합치면 끝난다.

### 4-3. vnavmesh 설정 파일 없음 — 고치지 않는다 (W-08, 버림)

기동마다 `pluginConfigsnavmesh.json` FileNotFound로 `[ERR]`이 하나 뜨고 기본값으로 진행한다. 남의 플러그인이 자기 설정을 아직 저장하지 않았을 뿐이고, **업스트림도 이걸 손으로 만들어 주지 않는다.**

우리가 만들어 주면 vnavmesh 스키마에 우리가 묶인다. 그쪽이 필드를 바꾸면 우리가 깨진다. **남의 것은 남이 관리하게 둔다** — vnavmesh 전반의 방침과 같다(§3).

`run\log.bat`이 오류 개수를 세므로 이게 1건인 상태가 정상이라는 것만 알고 있으면 된다.

## 5. 한국어화 — 규칙은 정해졌고 착수 전

**모드 안내는 전부 영어다.** 게임이 주는 텍스트(NPC 이름·대사·창 제목)는 이미 한국어로 읽힌다. 둘을 구분한다.

**규모를 잘못 세고 있었다.** 삼항만 세서 "675문장"이라고 말해 왔는데, 텍스트가 삼항 말고 다른 데도 있다.

| 어디 | 몇 개 | 스냅샷이 지키나 |
|------|-------|------------------|
| `AccessibilityStrings` 삼항 | 676쌍 (6개 옮김) | **예** — 옮긴 뒤에도 잡힌다 |
| 삼항인데 모양이 복잡해 못 읽은 것 | 40곳 | 아니오 — [유형별 정리](ko-hand-cases.md) |
| `CharaMakeIconText` 튜플 사전 | 1,928건 | **아니오** |
| `CharaMakeShapeText` 튜플 사전 | 1,095건 | **아니오** |

**캐릭터 생성 묘사가 본체보다 4배 이상 많다.** 얼굴·머리모양·눈매를 사람이 손으로 묘사한 글이라 그렇다. `(De, En, BriefDe, BriefEn)` 튜플이라 삼항을 읽는 스냅샷 밖에 있다(W-12).

`CharaMakeShapeText.cs`는 **자동 생성물**이라 파일을 직접 고치면 안 된다 — `tools/icons/shapes.tsv`에 한국어 열을 붙여 다시 만든다. 그쪽이 오히려 쉽다.

**결정 셋은 2026-08-18에 내려졌다.** 문체는 혼합(자주 들리는 짧은 안내=명사형, 도움말=해라체), 용어는 게임 한국어판을 따르고, 게임이 준 텍스트는 조사까지 그대로 둔다. 근거와 적용법은 [ko-localization 스킬](../.claude/skills/ko-localization/SKILL.md)이 갖는다.

**옮기기 전 원본을 찍어 뒀다** — `tools/strings-golden/golden/de-en.json`. 676쌍을 한 자 단위로 대조한다. 위 표의 "아니오"들은 아직 못 지킨다.

**용어 하나를 지어냈다가 잡혔다.** 스킬에 `Aetheryte → 에테라이트`라고 "결정"으로 박아 놨는데 로그·덤프 전체에서 그 표기가 **0건**이었다. 지웠다. 확인된 것만 표로 남기고 모르는 셋(Aetheryte·Action·Logout)은 모른다고 적었다. 게임 데이터에서 직접 뽑는 도구가 W-13이다.

단계와 순서는 [ko-client-port-feasibility.md](ko-client-port-feasibility.md) §13이 이미 갖고 있다. 여기 베끼지 않는다.

## 6. 업스트림 통합 — 무엇이 갈 수 있나 (W-10)

우리 패치 6건을 하나씩 판정했다. **절반은 못 올린다.** 못 올리는 이유가 정치가 아니라 구조라서, 따로 관리하는 쪽이 기본값이다.

| 패치 | 무엇 | 보낼 수 있나 | 왜 |
|------|------|--------|-----|
| 0001 | 기어세트 마크 shim | **아니오** | 로케일이 아니라 ClientStructs 버전 문제다. 업스트림은 7.55를 고정하고 그 함수를 갖고 있다 — 올려도 죽은 코드다 |
| 0002 | 노드 가시성 우회 | **아니오** | 0004가 폐기했다. 이력으로만 남는다 |
| 0003 | 한국어 확인 버튼 라벨 | **일반화하면 예** | 지금은 독일어 리터럴이 박혀 있다. 라벨을 데이터로 빼면 **프랑스어·일본어 클라이언트에서도 고쳐진다** — 업스트림 이익이다. 그게 W-07 |
| 0004 | 게임 함수로 되돌리고 경로를 말함 | **쪼개면 절반** | 얼개(CS가 주소를 못 채웠을 때만·정확히 1건일 때만·아니면 물러섬 + 어느 경로가 살아 있는지 보고)는 일반적이다. **시그니처 바이트는 KR 전용**이다 |
| 0005 | 언로드 때 폴백 포인터 회수 | 0004를 따른다 | 0004 얼개의 버그 수정이다. 따로 갈 수 없다 |
| 0006 | 설치기 KR화 | **아니오** | 프로필 루트·부트스트랩·플러그인 출처가 전부 KR 사실이다 |

`Compat/`는 통째로 우리 것이다. 그 판단은 코드에 적혀 있다 — `CompatReport.cs:35`: *"Korean-overlay only. Upstream rewrites that file constantly and every line we add there is a merge conflict."*

**따로 관리하되, 갈 수 있는 것만 골라 올린다.** `patches/`가 그 자리이고, **쌓아만 두는 게 아니라 로컬에도 먼저 적용된다** — 깨지면 보내기 전에 우리가 안다([patches/README.md](../patches/README.md)).

지금 보낼 수 있는 것은 넷이고 하나는 이미 넣었다.

1. **W-04 키 이름 표 통합** (§4-2) — KR 무관이고 근거가 가장 단단하다. 첫 PR로 적합
2. **W-07 게임 UI 라벨 외부화** (0003이 국지 대응한 것) — 다른 로케일도 고쳐진다
3. **0004의 얼개** — "CS가 비운 주소를 시그니처로 메우고 어느 경로인지 말한다". KR 언급 없이 성립한다
4. ~~타이틀 메뉴 개수~~ — **`patches/0001`로 들어갔다** (§9)
5. ~~언어를 하나 더 넣기 쉽게 만든 것~~ — **`patches/0002`로 들어갔다.** 한국 언급이 없고 프랑스어·일본어에도 그대로 쓸 수 있다
6. **있으나 마나 한 갈림길 하나** — `AttributeValue`는 독일어와 영어 분기가 글자까지 같다. 지우면 한 줄 준다 ([상세](ko-hand-cases.md))

**보류 이유는 기술이 아니라 절차다.** 업스트림 PR 언어(독일어/영어)를 아직 안 물어봤다(§7 D-4, [commit-rules.md](commit-rules.md) §5).

### 업스트림을 어떻게 따라잡나

이미 정해 뒀다 — [ko-client-port-feasibility.md](ko-client-port-feasibility.md) §12 "업데이트 추종 전략". 요지만 옮긴다.

- vendor는 **릴리스 태그 단위로만** 움직인다. 업스트림은 주 30커밋에 거의 매일 릴리스라, 커밋 단위로 쫓으면 따라잡는 일이 본업이 된다
- 태그를 올릴 때마다 패치 6건이 붙는지부터 본다. 그게 조기 경보다 — 지금은 pristine `main`에 전부 깨끗이 붙는다(2026-08-18 확인)
- **우리가 들고 있는 패치가 줄어드는지 본다.** 보낸 게 받아들여지면 줄어든다. 안 줄고 늘기만 하면 원본에서 점점 멀어지는 중이다

## 7. 판단이 필요한 것

| # | 사안 | 왜 사용자 판단인가 |
|---|------|--------------------|
| D-1 | 릴리스 채널을 열 것인가 | GitHub 릴리스 공개는 외부 영향이다. 열지 않으면 설치기는 로컬 빌드만 쓴다 |
| D-2 | 방위 안내를 `N`에서 어느 키로 옮길 것인가 | 게임 조작 습관은 사용자 것이다 (§4-1) |
| D-3 | 업스트림 **PR** 언어 | 트레일러는 영어로 정했다(2026-08-18). **PR 본문 언어는 첫 PR 직전에 업스트림에 묻는다** — 유지관리자가 TTS로 읽어서 독일어가 유력하다 |

## 8. 이 문서를 쓰는 법

**기능 구현·수정·개선을 시작할 때 여기를 먼저 연다.** 없는 일을 하지 않고, 하는 일에 ID를 붙인다.

- 새 일이 생기면 `W-NN`을 새로 딴다. **ID는 재사용하지 않는다.**
- 상태는 `대기` → `진행` → `완료`. 접는 것은 `보류`(막힌 것)와 `버림`(안 하기로 한 것)으로 구분한다.
- 완료한 항목은 §2 표에서 **지우고** §9에 한 줄로 옮긴다. 표가 길어지면 아무도 안 읽는다.
- §1 "지금"은 **덮어쓴다.** 이력을 쌓지 않는다 — 이력은 git log가 갖는다.
- 근거는 여기 쓰지 않는다. `docs/`의 해당 문서에 쓰고 여기서는 링크한다.

**커밋이 이 규칙을 강제한다.** `[업스트림]`·`[한국전용]`·`[검증]`·`[도구]` 커밋은 이 파일을 같이 건드리거나, 안 건드리는 이유를 트레일러로 밝혀야 한다. 검사기는 `tools/commit-lint`의 C8이다.
